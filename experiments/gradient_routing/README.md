# Count-priority gradient routing: mechanism passes, AdamW boundary remains open

Status, 2026-09-14: **authored mechanism and fixed-packet diagnostic complete;
not ready for a musical fit or production admission**. No old weights, CNN,
clock recurrence, loss, fit result, support mask or shipping default was changed.

## What is being tested

The earlier audit found phase/count gradient interference in both the period
output row and shared CNN. This experiment keeps that same network and forward
path. It changes how two already computed gradients are combined, without a
new model branch, extra loss weight or per-song selection policy.

Let c be the original native count-loss gradient and p the phase-loss gradient.
For each disjoint group (period output row, shared CNN, remaining phase/origin/
gain parameters), keep c and remove only p's opposing component:

```text
p' = p - min(0, dot(p,c) / dot(c,c)) * c
g  = c + p'
```

Zero c has no protective direction: keep p and explicitly report undefined
protection. In exact arithmetic dot(g,c) >= ||c||^2 for every nonzero group.
This is a local Euclidean count-descent property, not a BPM accuracy score.
The direct native-prior gradient is only a diagnostic comparator; it NEVER
enters the routing rule. Native count supervision still has imperfect alignment
with that comparator, so protecting count is not identical to supervising prior.

All recordings must first be weighted and summed into the complete batch, then
routed, then globally clipped once. Projection is nonlinear: independently
projecting recordings and adding them is a different algorithm. The binary-
exponent representation is retained and numerical protection is rechecked after
group recombination; lost alignment fails closed. No optimizer step is installed
by route(), and no recurrence derivative is truncated or detached.

## Authored learnability and the optimizer counterexamples

The [authored result](authored-v1.json) uses a fixed short reference generated by
the unchanged CNN/clock teacher, then 40 plain-SGD updates from the fixed student
initialization. The reachable synthetic task reduces phase loss 0.10858 ->
0.03140 and native count loss 0.007531 -> 0.001449. This is actual SYNTHETIC
optimization, not music fitting, encoder learning, a finite-step monotonicity
claim or evidence that natural audio supplies the authored fields. Separate
constant/step/ramp/zero-observation-gap controls preserve the earlier coherent
unsmoothed clock's representational capability. CPU/T4 checks cover all parameter
groups and unchanged forwards; no old model weights are loaded.

Gradient-only routing nevertheless fails the optimizer-admission requirement:

- With c=(2,1), p=(-3,6), routing keeps g=(-1,7) and dot(c,g)=5 > 0.
  A real first AdamW step approximately follows delta=(+0.01,-0.01), because
  the adaptive scaling differs by coordinate. Then dot(c,delta)>0: the count
  objective increases. No history is needed for this counterexample.
- After ten authored negative-gradient updates, AdamW momentum can still move
  a scalar parameter upwards when the newly supplied protected gradient is
  positive. The actual local count objective again increases.

These optimizer witnesses use lr=0.01 and zero weight decay to isolate the two
mechanisms; they are not a replay of the earlier fit's AdamW history. Both use
the real optimizer implementation, not a hand-waved update approximation. The
read-only displacement_check() detects their ACTUAL parameter changes, including
native rounding, and distinguishes zero movement from absent count direction.
It does not approve an optimizer or guarantee finite-step loss reduction: even
an orthogonal step can increase a curved loss. Exactly opposing gradients also
show why the method may discard all phase learning in a group; simultaneous
strict improvement cannot be promised for conflicting objectives.
